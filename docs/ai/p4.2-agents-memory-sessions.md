# P4.2 Agents, Subgraphs, Supervisors, Memory, and Sessions

P4.2 adds a provider-free LangGraph-style execution boundary for reusable AI
agents. Python remains the only orchestration authority (`python-langgraph`).
TypeScript, Bedrock Agents/Flows, and provider SDKs do not execute graph work.

## Execution boundary

`AgentRuntime` owns the agent, subgraph, and supervisor catalogs. An agent can
provide a handler directly or declare a bounded set of subgraphs. A supervisor
may select only one of those declared subgraphs; an undeclared selection fails
closed. Definitions must use the canonical LangGraph authority and are
versioned by `(name, version)`.

Every execution carries the existing `RuntimeContext` with tenant, actor,
correlation, idempotency, contract-version, and lineage fields. Session and
memory lookups are keyed by tenant and actor, so an identifier from another
tenant or actor cannot disclose or overwrite state. A handler cannot change the
authoritative context during execution; the runtime restores it from the
request before catalog persistence.

## Resume-safe local harness

The local harness uses `InMemorySessionCatalog` and
`InMemoryCheckpointCatalog`. A paused execution stores a versioned checkpoint
and a session catalog row. `AgentRuntime.resume` loads the latest checkpoint,
increments the resume count, and executes the same registered agent. Completed
sessions return their stored result on repeated resume, making retries
idempotent without re-running the handler.

The catalog row records `session_id`, `thread_id`, agent/version, status,
version, tenant/actor context, state, checkpoint ID, and checkpoint version.
The existing P3.3 checkpoint service remains the versioning and actor-scope
primitive underneath this facade.

## Memory catalog

`InMemoryMemoryCatalog` stores deep-copied, versioned rows keyed by tenant,
actor, optional session, and memory key. It is a deterministic fake for local
tests only. `UnavailableMemoryCatalog` is the explicit fail-closed adapter for
future PostgreSQL/Redis/vector-backed persistence; no database, cloud, provider,
credential, secret, or `.env` call is made by P4.2.

## Evidence and rollback

Focused coverage is in
`tests/compatibility/test_p4_2_agents_sessions.py`. It covers authority,
composition, cross-tenant and cross-actor isolation, supervisor escape
prevention, deep-copy/version behavior, pause/resume, tampered context
restoration, and idempotent completion. The runtime harness is deterministic
and local only.

Rollback is limited to the P4.2 AI catalog modules, the two canonical catalog
`get` methods, this document, the focused tests, and the P4.2 task/progress
metadata. P3.1–P4.1 contracts and runtime behavior remain intact.
